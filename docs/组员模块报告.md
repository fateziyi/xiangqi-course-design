# 中国象棋总体设计、象棋规则与 AI 核心模块实验报告

## 实验任务

按当前分工，本模块负责总体设计、象棋规则与 AI 核心，包括系统模块边界、接口契约、权威规则、局面表示和终局裁决、自研搜索与评估、独立 AI 服务及第三方引擎适配。界面交互、对局管理与系统测试由组长负责，双方共同完成接口联调。目标是在网页交互、权威规则和独立计算之间形成清晰接口，使人机与 AI 对 AI 对战使用相同规则，并在搜索期间保持界面可操作。

## 方案设计

采用 TypeScript 网页与 Python 服务分工。规则包不依赖网络或界面，对局服务是唯一状态修改者；AI 返回建议着法，对局服务验证后执行。所有异步响应关联对局 ID 和状态版本，新局或悔棋后拒绝旧结果。

棋盘为长度 90 的整数数组，正负区分红黑，绝对值区分棋子。局面保存行棋方、无吃子计数和局面键历史；纯规则层使用不可变 `Position` 表示，向对局管理模块提供落子和结果查询接口；组长维护的对局管理保存历史序列以支持悔棋和回放，双方核对吃子计数与重复历史恢复的一致性。

## 关键实现

规则先生成棋子候选目标，再模拟落子检查己方将帅安全。马腿、象眼、炮架、九宫和过河由棋子规则处理；将帅照面、将军与解将由攻击关系处理。将死和困毙均判行棋方负；重复与无吃子和棋规则按课程版处理。

AI 使用 Negamax 统一红黑搜索方向，使用 Alpha-Beta 剪枝跳过不能改善结果的分支，并用迭代加深在时间预算内逐层完成搜索。静态评估包含子力、位置与将帅安全。搜索在独立进程中运行，网络事件循环仍可接收取消请求。

根据用户提供的标准模式败局，升级版进一步加入吃子静态搜索、完整应将、PVS 窄窗口与重搜、请求内历史安全置换表、杀手/历史排序及走法缓存。第一轮保持旧位置权重，第二轮增加机动性、阶段马炮价值和王区压力，预计算几何加速规则并增加迭代窗口。自研标准 8/1500、强力 12/10000。另接入注明来源的 Pikafish，通过本项目 UCI 适配器处理历史、合法性和进程取消；第三方搜索及 NNUE 权重不能记为个人原创成果。纯自研棋谱仍 v1，含皮卡鱼使用 v2，新程序兼容导入两版。

总体设计约定通信使用 JSON 文本和固定版本。组长维护的对局服务校验请求、版本和控制方，并调用共享规则验证走法；本模块的独立 AI 服务校验局面和搜索参数。异常搜索不自动改用随机走法，而是暂停对局，保留棋盘并显示原因。

## 测试与结果

系统测试由组长统筹，本模块协助核对规则和搜索预期、解释棋力实验。既有测试包括标准初始局面 44 个合法走法、七类棋子正反例、自陷将军、将帅照面、将死、困毙、和棋优先级、重复请求、取消、断连和棋谱重放。10 个固定一步将死局面用于核对明确战术。40 局标准配置对基础配置保留环境、配置、版本哈希、逐步搜索数据与棋谱。

最新通过数量和棋力结果以同目录 `acceptance.md`、`棋力升级说明.md` 与对应实验目录为准；`experiments/baseline` 是升级前历史实验，不代表当前版本。与指导教师的实战仍需现场完成。

## 问题与改进

有限深度仍会导致地平线效应；静态搜索和排序只能缓解，不能保证达到某个人类等级。固定战术集合集中覆盖车的杀法，新加的吃子陷阱和用户败局回归也不能全面证明棋力。进一步改进需保留对照数据，按 SPEC 补充测试。

规则集未实现完整竞赛长将长捉责任裁决。数据仅驻留内存，重要棋谱需要导出。上述边界必须在答辩中准确说明。
