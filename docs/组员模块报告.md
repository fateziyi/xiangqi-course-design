# 中国象棋界面与对局验证模块实验报告

姓名与学号：提交前由本人填写。角色：组员。本文为责任范围对应的技术报告稿；独立实现、协助实现与测试验证需本人如实区分。

## 实验任务

本模块围绕棋盘显示、点击交互、模式设置、对局记录、回放、悔棋以及功能测试展开。目标是把对局服务的权威状态转换成清楚的操作界面，并让用户能保存、检查和恢复对局过程。

## 界面设计

网页采用棋盘与右侧操作栏布局。棋盘显示九宫、楚河汉界、红黑棋子、最后一步和合法目标；红方为朱红、黑方为深墨，绿色用于合法落点与推荐。窄屏依次排列棋盘与控制，避免挤压棋盘。

棋子与目标通过 SVG 坐标绘制，行列映射与服务端数组保持一致。棋盘交互元素有行列和棋子名称，可使用鼠标或键盘操作。前端不独立实现象棋规则，而是使用服务端返回的合法走法列表。

## 交互与状态

用户先选择己方棋子，再选择合法目标。AI 方、暂停、回放或终局不接受人类落子。人机模式可以执红或执黑，双方 AI 参数在新局时生效。当前行棋方、思考状态、将军和终局原因分别显示。

撤销一步退回一个半回合；人机撤销一轮退回最近一次人类行棋前。所有悔棋后暂停，避免 AI 立即走回原步。回放支持起点、上一步、下一步和终点；从节点继续前确认截断后续历史。

导出生成版本化 JSON 棋谱，导入由后端从初始局面逐步验证。前端展示失败原因，校验失败不替换当前对局。断连后禁止操作，重连恢复完整状态且由用户手动继续。

## 测试方法

界面测试应核对初始 32 子布局、每个选中棋子的目标点、红黑轮换、AI 推荐与实际落子的区别、各控制状态按钮可用性、历史导航与导入导出往返。

服务测试进一步检查非法棋谱保持原局、悔棋恢复计数、终局统计不重复累计以及过期 AI 结果不会污染新局。浏览器检查桌面与窄屏、错误日志、遮挡、点击响应和搜索时暂停。截图及实际执行记录保存在 `screenshots` 与 `acceptance.md`。

## 结果与边界

实际通过项以 `acceptance.md` 为准。标准与基础 AI 棋力数据仅来自已保存实验，不由界面动画推断。课程版和棋规则与服务重启不保留内存局的限制在页面中明确披露。
